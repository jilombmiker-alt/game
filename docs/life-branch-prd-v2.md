## 1. 文档目的

本 PRD 用于说明《人生岔路》从互动故事 Skill 实验、小型独立世界、中型长篇世界，到九界连续正史的完整产品演进。它同时承担三项任务：让教师理解为什么要做、让开发与内容生产使用同一套事实、让测评人员知道什么结果才算真正完成。

当前事实以 2026-08-17 的线上版本和仓库实现为准。早期方案中曾出现过不同的故事名称、幕数和上线节奏，本文件把这些变化保留在“版本演进”中，不把已废弃方案混入当前验收口径。

## 2. 产品摘要

《人生岔路》是一款无需登录、在浏览器中直接游玩的多世界互动叙事产品。玩家进入一个有明确资源边界、人物立场和倒计时的世界，通过三选一决策与关键节点自由输入推动剧情。选择会改变公共指标、人物的信任/亲近/同路关系、永久事实、线索和结局；死亡、决裂、失权、生态损失等结果不会被后文自动撤销。

产品现有 11 部完整故事，共 500 幕、71 个结局、103 个关键自由输入节点。前 9 部故事既可以独立游玩，也可以由玩家选择一条已通关分支作为正史，继承到两部大型连续世界。L01 读取九界正史，L02 再读取九界与 L01 的结果。

“AI 驱动”主要体现在两层：一是用 AI 辅助完成需求澄清、世界观设计、角色冲突、长篇内容生产和测试资产生成；二是把玩家自然语言输入归一到可执行路线。当前线上运行时采用可复现的本地语义路由和状态机，不依赖远程大模型，因此离线式本机存档、回放一致性和隐私边界更容易验证。

## 3. 问题、证据与产品机会

### 3.1 用户问题

传统轻量分支故事常见四个问题。

1. 选择只改变下一段文案，很少形成跨章节后果。
2. 人物容易成为玩家的工具，高好感可以抹掉角色底线。
3. 自由输入看似开放，实际无法稳定映射到剧情状态。
4. 前作结束后，制度、人物命运和世界伤痕无法进入下一部作品。

用户此前试玩时还暴露出一个直接问题：背景词藻多于任务解释，玩家不清楚“自己是谁、冲突是什么、要帮助谁、会付出什么”。因此本产品把可理解性视为核心质量，而不是把晦涩当成深度。

### 3.2 产品机会

产品不追求无限生成故事，而是把有限、可测、可回放的状态机与足够长的叙事结合。每幕必须新增行动、事实、风险或关系变化；关键决定要有即时回声、中期回声和结局回声；大型世界继承公共制度和永久事实，不复制玩家姓名、自由输入原文或私人关系数值。

由此形成差异化：玩家获得“我的选择被世界记住”的连续感，内容作者获得可审计的因果结构，产品经理能够用明确测试证明叙事质量，而不是只用“故事好看”作主观判断。

## 4. 产品定位与目标用户

### 4.1 产品定位

AI 协作开发的多世界互动叙事产品。核心价值主张是：每次选择都有可追溯的承担者，每个世界都能保留自己不同的答案。

### 4.2 核心用户

第一核心用户定义为“16 岁以上、喜欢深度故事、道德抉择与多周目探索的文字冒险玩家”。选择这一人群的原因如下。

- 中型与大型故事时长较长，需要愿意阅读和复盘的用户。
- 玩法强调公共伦理、人物边界和制度后果，不适合以即时数值爽感为唯一目标的用户。
- 产品无强社交、付费成长和操作竞技，吸引力来自角色、因果与结局探索。

第二用户包括互动叙事创作者、AI 产品经理学习者和希望观察人机协作生产流程的教师或面试官。

### 4.3 核心用户任务

- 快速理解世界、玩家身份、眼前危机和第一项任务。
- 在信息不完整且资源有限时作出选择，并看见代价落到具体对象。
- 用自然语言表达固定选项未覆盖的意图。
- 查看关系、线索、术语、永久事实和时间线，理解结果如何产生。
- 保存、回退、建立新分支，探索其他结局而不覆盖原有历史。
- 选定一条通关分支成为后续正史，观察旧决定如何改变大型世界。

## 5. 产品目标与非目标

### 5.1 当前目标

1. 让 11 部故事在同一入口下可被发现和独立游玩。
2. 保留四部旧世界原运行方式和原 localStorage 键，不覆盖用户旧存档。
3. 让五部中型世界采用统一引擎并全部上线。
4. 让两部大型世界各包含 100 幕、20 个自由输入节点和 8 个结局。
5. 让九界正史可以只读继承到 L01，L01 结果继续继承到 L02。
6. 用自动测试与人工测评共同证明结构完整、结局可达、存档隔离和叙事连续。

### 5.2 非目标

- 不做账号、云存档、排行榜、付费系统或多人联机。
- 不把实时调用大模型作为通关的必要条件。
- 不承诺任意输入都生成无限新剧情；超出世界能力的输入需要解释限制并给出邻近可执行方向。
- 不用好感值替人物签署同意，也不保证所有角色都能被拯救。
- 不把九个世界合并成单一文明。联盟只通过有限通道合作，各世界保留拒绝、退出和本地规则。

## 6. 产品设计原则

1. **先讲清冲突，再要求选择。** 第一幕用白话说明世界、身份、关键术语、倒计时、阵营和当前任务。
2. **资源不能凭空增加。** 每个方案必须写出受益者、承担者、执行者和停止条件。
3. **人物有自己的目标。** 高关系只能改变沟通方式，不能取消人物底线。
4. **重大后果不可随意回滚。** 死亡、失权、决裂、封门、生态与档案损毁进入永久事实。
5. **选择必须留下回声。** 关键决定至少在同章后续与结局各出现一次可见影响。
6. **自由输入先理解否定和歧义。** 无法确定时澄清，不静默替玩家选择。
7. **继承公共后果，不搬运私人文本。** 后作读取制度、人物公共命运、世界伤痕、资源债和来源哈希。
8. **存档属于玩家。** 本地分支不因正史选择被删除，后作只读快照不覆盖前作。

## 9. 核心体验循环

1. 玩家从故事库选择世界，首页显示类型、主题、幕数和本机进度。
2. 开始前选择能力倾向和价值立场；这只影响可用信息或初始表达，不替玩家决定结局。
3. 第一幕说明背景、身份、危机、规则与第一任务。
4. 玩家阅读行动场景、角色对白、线索与代价，选择三个方案之一。
5. 关键幕允许自由输入，系统识别否定、对象、优先级和底线，映射到作者定义路线。
6. 引擎原子更新指标、三维关系、资源、线索、事件与永久事实。
7. 后续幕根据当前状态显示不同回声；角色可支持、拒绝、离开或主动行动。
8. 章节检查点允许回退并建立新分支，不覆盖父分支。
9. 结局页解释世界结果、人物归宿、关键因果和代价，并解锁世界档案。
10. 玩家可导出存档、重玩，或选择一条已通关分支作为后续正史。

## 11. 功能需求

### 11.1 故事发现与公开访问

- 首页必须展示 11 部故事，并按小型、中型、大型分组。
- 每张卡展示标题、题材、主题、幕数、简介和本机进度。
- 无登录用户可以进入、游玩、保存、导出和阅读产品文档。
- 旧四部故事继续使用原路由和原存档键。

### 11.2 第一幕与叙事清晰度

- 第一幕必须回答五件事：世界是什么、玩家是谁、危机是什么、主要阵营是谁、当前第一任务是什么。
- 新术语首次出现时提供“是什么、造成什么影响、为什么现在重要”。
- 每幕至少新增行动、事实、风险或关系变化，不允许连续两幕只铺氛围。
- 五名首次玩家中至少四人能在阅读第一幕后 15 秒内说清冲突、帮助对象和主要代价。

### 11.3 三选项决策

- 普通幕默认提供三项互斥、都可执行的行动。
- 每项必须同时展示可见收益和具体代价，不使用“正确/错误”标签。
- 选项 ID 在单个故事内唯一，非法或不属于当前幕的 ID 必须被拒绝。
- 指标变化、关系变化和事实写入必须一次完成；刷新不能重复结算。

### 11.4 自由输入

- 中型世界共 47 个、大型世界共 40 个自由输入节点；小型世界共 16 个。
- 每个节点只允许进入作者预先定义且经过测试的路线，不承诺无限生成。
- 系统优先处理否定词、对象、优先顺序、时间条件和不可逆意图。
- 两条路线同分、指代不清或输入互相矛盾时，页面要求澄清而不推进。
- 空白、纯标点、超长输入和越界幻想不改变状态。
- 自我牺牲、永久失权等高风险路线必须二次确认，取消后状态完全不变。

### 11.5 人物与关系

- 每名核心人物有公开目标、矛盾特征、底线、自主计划、语言特征和命运风险。
- 关系至少分为信任、亲近和同路三个维度，不能压成一个总好感。
- 人物可以在没有玩家命令时推进自己的计划。
- 高关系不能迫使人物越过底线；低关系也不能让人物无理由作恶。
- 动态人物未触发时，普通主线仍须完整可通关。

### 11.6 永久事实与状态优先级

- 永久事实包括死亡、伤残、人格中断、失权、决裂、封门、拆船、生态损失与档案损毁。
- 渲染人物文案时，永久事实优先于通用结局模板。例如已死亡人物不能显示“继续在职”，人格已拆分的主体不能被写成完整重聚。
- 同一检查点产生的 A/B 分支只读取各自事实，不得跨分支串线。
- 每个结局可追溯到跨至少两章的三项以上关键决定。

### 11.7 档案与命运提示

- 玩家可随时查看当前指标、人物关系、已知线索、术语、事件和永久事实。
- 命运提示只说明“某人可能失去什么”，不直接公开隐藏结局阈值。
- 线索必须能回到来源幕，不展示正文中不存在的伪线索。

### 11.8 结局与重玩

- 当前共 71 个结局，每个结局必须存在从新游戏开始的合法可达路径。
- 隐藏结局移除任一必要条件后应回落到合理普通结局，不能误命中或死档。
- 结局页先交代世界结果与人物命运，再提供主题反思。
- 每名核心人物的归宿包含状态、最后自主行动和具体代价。

### 11.9 存档、分支与兼容

- 存档默认写入当前浏览器 localStorage，无登录、无服务端上传。
- 11 部故事使用独立命名空间；导入错故事存档必须原子拒绝。
- 旧存档缺少后续新增的可选字段时使用安全默认值，其他状态不丢失。
- 回退检查点时保留父分支，创建新的分支 ID 和父子关系。
- 导入损坏 JSON、非法幕索引、未知人物、未知结局、超大文件或异常嵌套时，不改变当前进度。

### 11.10 九界正史继承

- L01 只读九个来源：S01–S04 与 M01–M05；L02 读取上述九界加 L01。
- 玩家有多个已通关分支时，应选择其中一条作为正史。其他分支继续保留。
- 没有旧存档时使用明确标注的作者默认历史，玩家仍可完整通关。
- 继承包只包含公共制度、人物公共命运、世界伤痕、资源债、异议和来源哈希。
- 不继承玩家姓名、自由输入原文、完整关系数值和私人感情类型。
- 大型世界开始时冻结继承快照；后续改动旧世界存档不偷偷改变正在进行的大型世界。
- 旧角色死亡不得因为回归而复活。动态旧角色根据有效正史选择，并承担可见剧情作用。

### 11.11 音频、视觉与可访问性

- 声景使用浏览器本地合成，不依赖外部录音资源；静音与音量不影响故事状态。
- 正文与背景对比度目标不低于 4.5:1，状态不能只靠颜色表达。
- 主要触控目标不小于 44×44px；320px 宽度下核心流程无阻断性横向滚动。
- 键盘可以完成开始、选择、自由输入、打开/关闭档案和确认操作。
- 弹窗具备焦点约束，关闭后焦点返回触发控件；支持减少动态效果。

### 11.12 隐私与安全

- 不要求真实姓名、手机号、邮箱、定位或社交账号。
- 玩家名、自由输入、关系值和完整存档默认只保存在本机。
- 玩家输入以纯文本渲染；HTML、脚本、SVG 事件属性和 Markdown 链接不得执行。
- 客户端代码与构建产物不得包含有效密钥或访问令牌。

## 12. 数据与继承模型

### 12.1 单次运行核心字段

| 字段 | 作用 | 约束 |
| --- | --- | --- |
| storyId / version | 识别故事和格式 | 不同故事不能互导 |
| branchId / parentBranchId | 标识当前分支及父分支 | 回退时新建，不覆盖 |
| actIndex / chapter | 当前进度 | 必须在合法范围内 |
| metrics / resources | 公共指标与有限资源 | 按故事范围钳制 |
| relations | 三维人物关系 | 不直接等于同意 |
| flags / events | 已发生行动和制度事实 | 原子写入、可回放 |
| permanentFacts | 不可逆结果 | 渲染时优先级最高 |
| clues / terms | 已解锁线索与术语 | 必须有来源 |
| endingId / unlockedEndings | 当前与历史结局 | 去重、可达性校验 |
| integrity / sourceHash | 导入和继承校验 | 篡改时拒绝 |

### 12.2 本机命名空间

四部旧故事保留 `neon-rain:current:v2`、`mist-harbor:current:v1`、`ember-north:current:v1`、`day-off:current:v1`。中型世界采用 `life-branch:medium:{world}:v1:*`，大型世界采用 `life-branch:large:{world}:v1:*`。不同层级不得共享 current 键。

### 12.3 继承流程

```text
已通关旧分支
  → 校验故事、版本、结局与完整性
  → 玩家选择正史
  → 提取公共后果白名单
  → 生成带来源哈希的只读快照
  → L01 开场显示来源与默认项
  → L01 结局生成第二层公共后果
  → L02 同时读取九界快照与 L01 快照
```

| 指标 | 目标 | 意义 |

## 15. 测评与发布策略

测评采用五层框架：产品价值、叙事与人物、交互与自由输入、工程与存档、体验与安全。综合评分为 100 分，因果连续性权重最高，为 25 分。理由是该产品的核心承诺不是“文字很多”，而是“选择经过长时间仍然成立”；一旦因果断裂，人物、自由输入和跨世界继承都会同时失去可信度。

发布必须同时满足三项条件：总分不低于 80；所有 P0 一票否决项通过；自动化与人工证据均存在。仅有自动测试通过不能证明故事清晰或人物成立，仅有人工好评也不能证明存档和结局可靠。

## 16. 风险与应对

| 风险 | 影响 | 当前应对 |
| --- | --- | --- |
| 长篇内容重复或灌水 | 玩家失去耐心，幕数失去意义 | 每幕新增信息检查、删减测试、章节因果审阅 |
| 状态组合爆炸 | 出现人物复活、串线或死档 | 永久事实优先级、代表路径与自动穷举 |
| 自由输入误解否定 | 执行与玩家相反的危险行动 | 否定优先、歧义澄清、不可逆二次确认 |
| 九界继承污染旧档 | 用户失去历史或后作正史错乱 | 只读适配器、来源白名单、冻结快照 |
| 动态角色误复活 | 破坏旧作结局可信度 | 只从始终存在且状态合法的候选中选择 |
| 本机存档跨设备不可用 | 用户更换浏览器后无法继续 | 提供导出/导入；当前不承诺云同步 |
| 无实时大模型被误认为“无限输入” | 预期落差 | 明示自由输入映射到作者路线，越界时解释限制 |
| 教师只看网站难理解产品过程 | 产品决策与测试价值不可见 | 教师总入口、PRD、评分标准、72条测评集和快速体验路线 |

## 17. 人机协作与作者职责

本项目由用户与 AI 协作完成。用户承担产品方向、题材排序、关键人物关系、世界冲突、上线方式、旧存档兼容和正史继承等决策；AI 辅助把选择整理成需求、内容数据、交互实现、测试与文档。最终取舍由用户确认，当前线上实现和测评证据可被独立复核。

在人机协作中，AI 输出不直接等于产品事实。每个世界必须通过结构校验、状态测试和人工叙事审阅；出现早期设定与当前代码冲突时，以明确版本和当前可运行产品为准，并在演进记录中说明变化。

## 21. 十一部故事的专项验收卡

以下验收卡把统一规则落到单部作品，教师可以据此判断“故事数量”是否真的形成了不同的产品问题，而不是只更换背景词。

### 21.1 S01《霓虹雨季》

- 核心承诺：被城市记忆系统删除的人仍拥有同意、拒绝和留下证词的权利。
- 不可逆事实：人物被移除、人格中断与根权限转移必须持续影响后文；公民陪审已接权时，玩家不能继续被写成唯一批准者。
- 抽查方法：分别走“保留集中权限”和“交给陪审”两条路径，比较同一高风险操作的执行主体与责任日志。

### 21.2 S02《雾港来信》

- 核心承诺：回复过去并不等于拥有改写他人命运的授权，证据公开范围由当事人的真实同意决定。
- 不可逆事实：只同意遮盖后公开的证据不能在结局变成完整公开；已确认的自我牺牲不能在尾声被普通身份撤销。
- 抽查方法：改变许棠的证据授权与最终制动者选择，验证公开内容、候选人和结局旁白同步改变。

### 21.3 S03《北境余烬》

- 核心承诺：龙蛋不是阵营资源，人类不能默认替另一种生命同意被孵化、武装或牺牲。
- 不可逆事实：受伤、阵营决裂、龙蛋归属与王权失效必须进入后续外交与结局，不能因好感较高自动和解。
- 抽查方法：对照“交给单一阵营”和“保留龙的拒绝权”路径，检查人物底线、资源与五个结局的合法性。

### 21.4 S04《今天别做主角》

- 核心承诺：玩家可以退出英雄位置，但不能用离开逃避已经承担的危楼、家庭和居民权利责任。
- 不可逆事实：有效交接必须写明接手人、资源、时限与检查方式；居民拒迁不能被一句“为了大家”抹除。
- 抽查方法：比较直接接管、完成交接与彻底逃离三条路径，确认系统区分休息权、卸责和共同治理。

### 21.5 M01《我们在废墟上发明明天》

- 核心承诺：七个聚落的能源、土地未来与无登记者生存权不能由单一效率指标代表。
- 不可逆事实：资源债、聚落退出、土地损伤与无登记者身份安排必须跨章累计，并成为九界继承的公共后果。
- 抽查方法：选择不同能源协议与登记制度，验证同一后期危机的可用资源、联盟成员和人物自主行动不同。

### 21.6 M02《借神之名》

- 核心承诺：把旱灾转移给别人并删除承担者姓名，不能因为结果被称作神迹就获得正当性。
- 不可逆事实：受灾地损失、具名证词、祭祀授权与王朝合法性持续存在；人物同意不能由玩家代签。
- 抽查方法：分别选择隐去姓名、公开代价与拒绝转移，检查制度评价、人物命运和隐藏结局条件。

### 21.7 M03《退潮线以内》

- 核心承诺：修正漏掉四万人的撤离名单会消耗真实时间和运力，公平与效率都要承担可见代价。
- 不可逆事实：罗岑与田树各自隐瞒一部分善意，拼在一起形成长期误会；澄清只能在关系结束或很晚之后发生，不能靠早期一句解释消除。
- 抽查方法：保留与公开不同善意信息，验证误会阶段、撤离资源、关系决裂与后期澄清的时间顺序。

### 21.8 M04《盐月沉入森林》

- 核心承诺：玩家是被森林异族养大的人类孩子；一族的生存方式持续破坏另一族栖息地，因此亲情不能自动消除生态冲突。
- 不可逆事实：栖息地损失、盐裔生存代价、养育关系与两族制度选择必须分开记录；高亲近不能伪造和平。
- 抽查方法：对照偏向人类、偏向养育族与承担双向限制的路线，检查生态指标、家庭称谓和结局代价。

### 21.9 M05《史书之外有长河》

- 核心承诺：现代知识只有转化为当代可执行的工料、组织和授权才有效；温暖家庭也保留判断与拒绝包庇的权利。
- 不可逆事实：全家陆续发现玩家已不是原来的人，却默契地不逼其承认；家人的体贴、帮忙扛事和热爱生活要通过具体日常行动表现。
- 抽查方法：改变身份诚实度、治河授权与原身功罪记录，确认顾家继续照顾但不会替公共受害者同意。

### 21.10 L01《九个世界没有共同的明天》

- 核心承诺：玩家以“九界通道仲裁员”身份处理容量降至三成的通道，任何排序都要公开谁先走、谁留下和由谁负责。
- 不可逆事实：九界各自独立，不被合并为同一世界；来源存档只读，死亡角色不复活，动态旧角色必须对主线产生实际作用。
- 抽查方法：使用作者默认历史和一组玩家正史各通关一次，比较来源提示、动态人物、联盟债务和八个结局。

### 21.11 L02《群星不接受统一答案》

- 核心承诺：迟到四十年的故乡命令、船生代权利和原生生命的拒绝同时有效，不存在天然拥有新世界的一方。
- 不可逆事实：L02 同时读取九界快照与 L01 公共后果，但不读取玩家姓名、自由输入原文或私人关系数值。
- 抽查方法：改变 L01 的通道制度与联盟结果，确认 L02 的开局资源、合法性冲突和八个结局随公共后果变化。

## 22. 关键产品决策记录

| 决策 | 当前选择 | 取舍理由 |
| --- | --- | --- |
| 旧站处理 | 保留整体气质并继续承载旧世界 | 降低迁移风险，让早期成果成为产品演进证据 |
| 第一阶段交付 | 线上链接直接可玩 | 教师可验证真实产品，不只阅读静态方案 |
| 旧世界运行 | 暂时保留各自既有引擎 | 先保证可玩和存档兼容，再逐步统一内部实现 |
| 存档策略 | 必须兼容当前浏览器旧档 | 玩家历史属于核心资产，不能因扩展世界被覆盖 |
| 中型世界发布 | 五部完成后一次上线 | 让五种题材共同证明中篇能力，避免只展示半套框架 |
| 大型世界 | 两部连续故事，九界影响 L01，L01 再影响 L02 | 把早期选择转化为跨作品公共后果 |
| 世界关系 | 九界独立，通过平行联盟相连 | 保留各世界价值差异，避免合并后因果被简化 |
| 玩家身份 | 九界通道仲裁员 | 为跨世界资源排序提供明确责任位置 |
| 教师材料 | 一个总入口，提供 PDF、DOCX 与 Markdown | 同时满足快速审阅、打印提交和可编辑复核 |
| 合格标准 | 80 分且 P0 全部通过 | 防止平均分掩盖存档损坏、人物复活等致命问题 |
| 证据边界 | 自动、人工、用户证据分级 | 不把“测试代码存在”冒充“真实玩家已经理解” |

这些决策并不表示所有未来版本都必须沿用。若后续统一旧引擎、增加云存档或接入实时模型，必须重新评估隐私、迁移、可复现性、成本与回滚方案，并更新版本号和测评集。
